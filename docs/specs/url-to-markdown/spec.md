# URL → Markdown 변환 후 LLM으로 넘기기

웹 페이지 URL을 붙여넣으면 본문을 Markdown으로 추출해 보여 주고, 복사·다운로드하거나 프롬프트와 함께 ChatGPT·Claude로 바로 열 수 있는 단일 화면 서비스.

## 관련 자료

- [UI 구성 원칙](../../decisions/ui-composition.md): 입력, 결과, 내보내기 영역의 component 선택, token, 상태 표현, 좁은 화면 배치를 정합니다.

## 사용자에게 보이는 결과

1. **입력**: URL 입력란에 주소를 붙여넣고 변환을 실행합니다. 지우기 버튼을 누르면 입력값과 결과가 모두 비워져 처음 상태로 돌아갑니다.
2. **변환**: 서버가 페이지를 가져와 defuddle로 본문만 추출하고 Markdown으로 바꿉니다. 변환 중에는 진행 중임을 보여 줍니다.
3. **결과 확인**: 결과 상단에 페이지 제목과 저자가 헤더로 보이고, 그 아래에 Markdown이 렌더링된 형태로 보입니다.
4. **내보내기**
   - 복사하기: Markdown 원문을 클립보드에 복사하고 복사됐다는 피드백을 줍니다.
   - .md 다운로드: Markdown 원문을 `.md` 파일로 내려받습니다.
   - ChatGPT로 열기 / Claude로 열기: 선택한 프롬프트(있으면)를 Markdown 앞에 붙여 새 탭으로 엽니다.
5. **프롬프트 선택**: 프리셋 "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘"와 "직접 입력" 중 하나를 고르거나 아무것도 고르지 않을 수 있습니다. "직접 입력"을 고르면 텍스트 입력란이 나타납니다. 직접 입력한 내용은 저장하지 않습니다.
6. **다크모드 토글**: 라이트/다크 테마를 전환할 수 있습니다.

## 범위

포함:
- 위 흐름 전체를 하나의 페이지에서 제공
- 변환 실패 시 오류 상태 표시

제외:
- 로그인, 변환 기록 저장, 직접 입력 프롬프트 저장
- hosted defuddle.md API 사용
- 여러 URL 일괄 변환, Markdown 편집

## 수용 기준

- 공개된 기사 페이지 URL(예: `https://stephango.com/file-over-app`)을 넣고 변환하면 제목 "File over app", 저자 "Steph Ango" 헤더와 렌더링된 본문이 보입니다.
- 저자 정보가 없는 페이지(예: `https://example.com`)는 저자 없이 제목만 헤더에 보이고, 빈 저자 자리가 남지 않습니다.
- 지우기를 누르면 입력란과 결과, 오류가 모두 사라집니다.
- 변환 중에는 진행 상태가 보이고 변환 버튼을 중복으로 누를 수 없습니다.
- URL 형식이 아닌 값을 넣거나, 대상 사이트가 요청을 거부하거나(예: HTTP 403), 본문을 추출하지 못하면 결과 대신 이해할 수 있는 오류 메시지가 보이고 다시 시도할 수 있습니다.
- 복사하기를 누르면 클립보드에 Markdown 원문이 들어가고 복사 완료 피드백이 보입니다.
- .md 다운로드를 누르면 Markdown 원문이 담긴 `.md` 파일이 내려받아집니다.
- 프롬프트를 고르지 않고 ChatGPT·Claude로 열면 Markdown만 전달됩니다. 프롬프트를 고르면 프롬프트가 Markdown 앞에 붙어 전달됩니다.
- 전달할 내용이 짧으면 새 탭이 `https://chatgpt.com/?q=…` 또는 `https://claude.ai/new?q=…` 형태로 열리고 입력창에 프롬프트와 본문이 채워집니다.
- 전달할 내용이 길이 기준을 넘으면 프롬프트+Markdown 전체가 클립보드에 복사되고, 새 탭은 프롬프트만 담아 열리며, 화면에 "클립보드에 복사했으니 붙여넣으세요"라는 안내가 보입니다. 본문이 잘리는 경우는 없습니다.
- "직접 입력"을 고르면 텍스트 입력란이 나타나고, 그 내용이 프롬프트로 쓰입니다. 새로고침하면 입력한 내용은 사라집니다.
- 다크모드 토글을 누르면 화면 전체 테마가 바뀝니다.

## 확정된 제약과 이유

- **추출은 defuddle 라이브러리로 합니다.** 사용자가 지정한 필수 조건입니다. 브라우저에서는 CORS 때문에 다른 사이트의 HTML을 직접 가져올 수 없으므로, 페이지 가져오기와 추출은 서버에서 합니다.
- **LLM 전달은 "URL 우선, 길면 클립보드 폴백"으로 합니다.** ChatGPT·Claude의 `?q=` URL에는 길이 한계가 있는데, 위키백과 문서 하나만 해도 Markdown이 수십 KB가 됩니다. 항상 클립보드만 쓰면 짧은 글도 매번 붙여넣어야 하고, 길이를 넘을 때 자르면 본문이 빠집니다. 그래서 짧을 때는 한 번에 열고, 길 때는 본문을 온전히 보존하는 쪽을 택했습니다 (사용자 확인).
- **프롬프트는 LLM으로 열기에만 붙습니다.** 복사하기와 .md 다운로드는 Markdown 원문만 다룹니다.

## 가정 (바꿔도 되는 기본값)

- URL 전달 길이 기준은 인코딩 후 URL 전체 약 8,000자로 둡니다. 실제 서비스 한계를 확인하면 조정합니다.
- 프롬프트와 Markdown 사이에는 빈 줄 하나를 둡니다.
- 프롬프트는 기본으로 아무것도 선택되지 않은 상태이고, 프리셋과 "직접 입력"은 한 번에 하나만 고를 수 있습니다. 선택한 것을 다시 누르면 해제됩니다.
- 다크모드는 처음에 시스템 설정을 따르고, 사용자가 토글한 값은 이 브라우저에 기억합니다.
- 결과 헤더에는 제목과 저자 외에 사이트 이름(또는 도메인)을 보조 정보로 함께 보여 줍니다.
- 다운로드 파일명은 페이지 제목을 파일명에 쓸 수 있는 형태로 바꾼 값이고, 제목이 없으면 도메인을 씁니다.
- 스킴 없이 `example.com`처럼 입력하면 `https://`를 붙여 처리합니다.
- 변환 결과 Markdown 앞에 제목·출처 URL 같은 메타데이터를 따로 붙이지 않습니다.

## 손대지 않는 영역

- `docs/decisions/`의 기존 결정 계약은 바꾸지 않습니다.
- 인증·저장소·외부 유료 API(defuddle.md hosted API)는 이번 범위에 넣지 않습니다. 스펙이 요구하지 않고 강의용 템플릿의 검증 예산을 넘습니다.
- 스펙이 요구하지 않은 보안 하드닝(SSRF 방어, 요청 제한 등)은 AGENTS.md의 검증 예산에 따라 범위 밖입니다.

## 미룬 결정

- **로그인이 필요하거나 봇을 막는 사이트 처리**: 현재는 오류 메시지로만 처리합니다(interim). 브라우저 확장이나 HTML 붙여넣기 같은 우회 수단은 별도 결정으로 미룹니다.

## 남은 위험

- ChatGPT·Claude의 `?q=` 동작과 길이 한계를 이 환경에서 실제로 확인하지 못했습니다(외부 접속 불가). 두 서비스가 파라미터 동작을 바꾸면 짧은 글 전달이 깨질 수 있으니, 구현 후 실제 브라우저에서 확인해야 합니다.
- defuddle 0.19.5를 스크래치에서 시험한 결과:
  - linkedom 0.18.14: 기사·위키백과·GitHub·react.dev 추출 성공. 응답 본문이 HTML이 아닐 때(예: 403의 `Forbidden`) 예외가 납니다.
  - jsdom 30.1.3: 추출은 되지만 일부 페이지에서 "Selector exceeds maximum allowed length of 2048" 오류 로그를 남기고 재시도합니다.
  - 어느 쪽을 쓰든 HTML이 아닌 응답과 HTTP 오류는 추출 전에 걸러 오류 상태로 보내야 합니다. defuddle이나 jsdom 업데이트로 selector 오류가 사라지면 DOM 라이브러리 선택을 다시 볼 수 있습니다.
- 일부 사이트는 서버 요청을 403으로 거부합니다. 이런 사이트는 변환할 수 없습니다. (구현 중 확인: `news.hada.io`는 기본 User-Agent에는 403을 돌려줬지만, 브라우저 User-Agent를 보내면 변환됩니다.)
- 클립보드 쓰기는 사용자 클릭 직후에만 허용되는 브라우저가 있어, 폴백 복사는 버튼 클릭 흐름 안에서 일어나야 합니다.
